# 책방틈 (Bookbangteum)

> 취향에 맞는 독립서점을 발견하고, 책방과 산책을 연결하는 모바일 중심 웹서비스

**최신 버전:** v0.4 (2026-11-16)  
**버전 기록:** v0.4 → v0.3 → v0.2 → v0.1 (최신순)  
**문서 구성:** 1. 변경이력 관리 → 2. PRD → 3. 공통 개발·운영 정보

이 문서는 각 시점의 **기획 요구사항과 실제 소스에 구현된 기능을 구분**해 기록한다. 버전 날짜는 각 버전의 기준일이며, 모든 개별 기능의 실제 코딩 날짜를 뜻하지 않는다.

# 2. PRD (Product Requirements Document)

# 서비스 한줄 소개
- 내 취향에 맞는 독립서점을 빠르게 찾고, 책방을 중심으로 산책·휴식 코스까지 계획하는 모바일 웹 서비스

# 배경과 문제 정의
- 독립서점을 찾는 사람은 지도 앱에서 "독립 서점"을 검색한 뒤, 책방을 하나씩 열어 보고, 블로그·SNS에서 **어떤 책을 다루는지 / 조용한지 / 혼자 가기 좋은지 / 앉아서 읽을 수 있는지**를 따로 확인해야 한다. 탐색 시간이 길고, 책방의 핵심 특징을 한눈에 비교하기 어렵다.

책방틈의 핵심 가치는 여러 책방을 많이 방문하는 것이 아니라 **"나에게 맞는 책방을 발견하는 것"** 이다. 산책은 서비스의 최종 목적이 아니라, 책방에서 책을 읽고 쉬기 전후의 여유로운 경험을 넓혀 주는 요소다.


## 2.1 PRD v0.4 — 2026-11-16 (최신)

### 제품 목표와 대상

- **목표:** 지역·취향·분위기별로 독립서점을 발견하고, 후기와 공간 정보를 참고해 방문할 책방을 정한 다음 산책 코스를 계획·저장한다.
- **대상:** 독립서점 탐방객, 혼자 책을 읽고 쉬려는 사용자, 산책과 책방 방문을 결합하려는 사용자.
- **환경:** 모바일 중심 반응형 정적 웹(HTML/CSS/JavaScript), 브라우저 저장소 기반 개인화.

### 기능 우선순위

- **Must:** 책방 목록/검색, 지역·테마·분위기·시설 필터, 상세정보, 출처 A/J 표시, JSON 로딩/오류 안내, 후기 작성 및 분위기 연동, 책방 위치/주소 확인.
- **Should:** 즐겨찾기, 최근 본 책방, 코스 만들기·편집·저장, 방문 기록, 취향 설정·추천, 모바일 탐색 편의(TOP).
- **Could:** 새소식 자체 목록·상세 화면, 검증된 기사/행사 데이터 연동, 사용자 간 후기·코스 공유, 클라우드 동기화.
- **제외/미구현 구분:** 실시간 혼잡도·재고·결제·예약은 범위 밖. 서버 기반 다중 사용자 후기 공유와 실시간 뉴스 수집은 현 버전의 구현 기능이 아님.

### MVP 및 완료 조건

1. 사용자가 지역·테마·분위기 조건으로 서점을 좁히고 상세정보를 확인한다.
2. 서점의 기존 태그 및 작성된 후기의 분위기 정보로 탐색 결과를 판단한다.
3. 관심 책방을 저장하고, 책방과 주변 장소를 활용해 코스를 만들고 재방문 시 불러온다.
4. 두 데이터 파일을 읽지 못할 경우 오류/재시도 또는 부분 로딩 안내를 제공한다.

### 사이트맵

```text
홈
├── 히어로(책방 소개) · 검색 · 추천 해시태그
├── 오늘은 이런 책방 어때요? (랜덤 2곳)
├── 새소식 (외부 뉴스 검색 연결)
├── 최근 본 책방
└── 내 취향 맞춤 추천 (로그인 조건)
책방 탐색
├── 책방 목록 · 검색/정렬/필터
└── 책방 상세
    ├── 주소 · 운영정보 · 출처 배지
    ├── 즐겨찾기 · 방문 기록
    └── 후기 작성/조회
코스
├── 코스 탐색/공유 코스 예시
├── 코스 조건 설정 · 지도/결과
└── 코스 편집 · 저장/완료
나의 책방 / 나의 취향
└── 즐겨찾기 · 방문 기록 · 저장 코스 · 취향 설정
로그인/회원가입/프로필 (브라우저 기반 데모)
```

### User Flow

- **A · 책방 발견:** 홈 검색/해시태그 → 책방 탐색 → 지역·테마·분위기·시설 필터 → 카드 비교 → 상세 → 즐겨찾기 또는 후기.
- **B · 후기 기반 필터:** 책방 상세 → 후기 작성(분위기 선택) → 저장 → 책방 탐색 → 같은 분위기 필터 → 해당 책방 노출.
- **C · 코스:** 책방 상세 또는 코스 화면 → 책방/주변 장소 선택 → 조건·순서 조정 → 결과 확인 → 저장 → 나의 책방에서 재확인.
- **D · 개인화:** 로그인(데모) → 취향 설정 → 홈 맞춤 추천 → 책방 상세.
- **E · 최근 기록:** 책방 상세 방문 → 홈 최근 본 책방 → 카드 재방문 또는 카드별 삭제.

### 데이터 구성 및 처리

- **기존 JSON:** `data/bookstores-local.json` — 100개, 화면 출처 `J`.
- **API 수집 JSON:** `data/bookstores-api.json` — 200개, 화면 출처 `A`.
- **주변 장소:** `data/places.json` — 16개.
- **공유 코스 예시:** `data/sharedCourses.json` — 7개. 정적 샘플 데이터이며 서버의 실시간 사용자 공유 목록은 아님.
- **수집:** `scripts/fetch_bookstores.py`가 문화공공데이터광장 OpenAPI에 접근해 응답을 JSON으로 저장. **웹사이트 접속 시 공공 API를 실시간 호출하지 않고** 이미 저장한 JSON을 읽는다.
- **개인 데이터:** 즐겨찾기, 방문 기록, 후기, 코스, 취향, 최근 본 목록 등은 브라우저 `localStorage`를 사용. 다른 브라우저·기기와 자동 동기화되지 않는다.
- **예외:** 누락된 서점 정보는 임의로 채우지 않으며, 로딩 실패와 결과 0건을 사용자에게 안내한다.

### 구현상 제약 및 확인사항

- 로그인/회원가입 UI는 클라우드 인증이 아닌 브라우저 기반 데모 방식이다.
- 새소식은 구글 뉴스 검색 링크로 이동한다. 기사 원문을 API로 수집·보관하는 기능은 없다.
- 후기 기반 분위기 필터는 **현재 브라우저에 저장된 후기 데이터**를 사용한다. 다른 사용자에게 공유되는 중앙 후기 DB는 없다.
- 지도 링크/표시와 실제 도보 경로 API의 실시간 계산을 동일한 기능으로 설명하지 않는다.

## 2.2 PRD v0.3 — 2026-11-02

### 목표

v0.2의 책방 탐색·후기·코스 기능을 유지하면서 **기존 JSON과 공공 API 수집 데이터를 명확히 구분**한다.

### 기능 우선순위

- **Must:** 책방 검색·필터·상세, JSON 100 + API 200 통합 로딩, A/J 출처 배지, 데이터 오류 처리.
- **Should:** 후기·즐겨찾기·최근 본 책방·코스·취향 설정 등 기존 기능 유지.

### MVP

기존 탐색 기능을 이용할 수 있고, 300개 서점의 데이터 출처를 확인할 수 있으며, API 키를 공개하지 않고 오프라인 수집한 JSON을 웹에서 읽는다.

```text
홈 → 책방 탐색 → 목록/필터 → 상세/후기
홈 → 코스 → 조건 설정 → 지도/결과 → 저장
홈 → 나의 책방 / 나의 취향

```

### User Flow

페이지 로딩 → `bookstores-local.json` + `bookstores-api.json` 읽기 → 데이터 통합 → 검색/필터 → 카드의 A/J 확인 → 상세정보 → 저장 또는 코스.

### 데이터 및 기술

- `bookstores-local.json` 100개 + `bookstores-api.json` 200개.
- `places.json` 16개 + `sharedCourses.json` 7개.

## 2.4 PRD v0.1 — 2026-10-12 (4주차 기획)

> 아래는 당시 7쪽 기획 문서의 **계획 범위**를 보존한 내용이며, v0.1의 실제 구현 완료를 뜻하지 않는다.

### 사용자 문제·시나리오

주말/공강에 추리소설과 조용한 공간을 좋아하는 사용자가 지도 앱, 블로그, SNS를 오가며 책방의 취급 분야·분위기·좌석·음료 여부를 각각 확인해야 한다. 서비스에서 조건을 복수 선택하고 방문자 후기 기반 태그로 판단한 뒤, 책방을 중심으로 산책/휴식 코스를 계획한다.

### 문제 우선순위

1. **취향에 맞는 책방 찾기:** 취급 분야·테마 복수 필터, 책방 특성 태그, 상세보기.
2. **실제 방문 경험 판단:** 체크리스트형 후기, 후기 응답 집계·키워드 요약, 후기 기반 추천 태그.
3. **책방 중심 경험 확장:** 책방 중심 산책 코스, 주변 장소·산책 경로 지도 표시.
4. **개인화·재사용:** 북마크, 방문 기록, 개인 메모.

### 기능 우선순위 (당시 원안)

- **Must:** 책방 목록, 지역 검색, 취급 분야·테마 복수 필터, 책방 특성 태그, 상세보기, 체크리스트 후기, 후기 응답 집계/키워드, 책방 중심 지도.
- **Should:** 책방 중심 산책 코스, 주변 산책로·휴식 장소, 북마크, 방문 기록, 개인 메모.
- **Could:** 취향 기반 책방 추천, 자유 후기 키워드 추출, 책방별 인기 태그 시각화.
- **제외:** 실시간 혼잡도, 실시간 재고/도서 검색, 예약·결제, 유저 생성 코스 공개 공유 플랫폼.

### MVP (당시 원안)

지역 → 취급 분야·테마 → 분위기·공간 조건 → 책방 목록 → 상세·후기 태그 확인 → 즐겨찾기 저장이 **1차 MVP**. 이후 책방 중심 산책·휴식 공간 지도 확인과 코스 구성이 심화 목표.

### 사이트맵 (당시 계획)

```text
홈
├── 책방 탐색
│   ├── 책방 목록
│   ├── 책방 상세
│   └── 방문자 후기/키워드
├── 코스 만들기
│   ├── 코스 조건 설정
│   ├── 지도·코스 결과
│   └── 코스 편집·저장
├── 나의 책방
│   ├── 즐겨찾기·방문 기록
│   └── 저장 코스
└── 나의 취향
    └── 취향 설정·추천
```

### User Flow (당시 계획)

- **흐름 A · 취향에 맞는 독립서점 찾고 저장:** 서비스 진입 → 지역 선택 → 취급 분야·테마·분위기·시설 필터 → 카드 비교 → 상세·후기 확인 → 즐겨찾기 저장.
- **흐름 B · 저장한 책방으로 독서·힐링 코스:** 나의 책방 → 즐겨찾기 선택 → 산책/독서 체류 조건 설정 → 지도·코스 결과 → 이동 정보 확인(지원 시) → 장소/순서 편집 → 코스 저장.
- **예외 흐름:** 로딩, 결과 없음, JSON/클라우드 DB/지도 API 오류, 저장 실패, 후기 부족, 지도/경로 API 미지원 시 안내와 재시도 제공.

### 데이터·외부 연계 (당시 계획)

- **JSON:** 서점 기본정보·상세·위치.
- **Supabase/Firebase 등 클라우드 DB:** 여러 이용자의 후기 저장·조회·집계 **계획**.
- **지도 API/경로 API:** 책방 마커·주변 장소·도보 경로·예상 시간 **계획**, 지원 여부 확인 필요.
- **LocalStorage:** 즐겨찾기·코스·취향 등 개인화 저장 **계획**.

# 3. 공통 개발·운영 정보

## 3.1 기술 스택

- **프런트엔드:** HTML5, CSS3, JavaScript
- **정적 데이터:** JSON
- **API 데이터 수집:** Python, 문화공공데이터광장 OpenAPI
- **개인 데이터 저장:** 브라우저 LocalStorage
- **실행/배포:** 로컬 정적 웹서버(VS Code Live Server 등), GitHub Pages에 배포 가능한 구조

## 3.2 생성형 AI 도구

프로젝트의 기획·설계·개발 보조에 활용하는 생성형 AI 도구:

- **ChatGPT** — 기획 정리, 요구사항/문서 작성, 코드·디버깅 지원
- **Claude** — 구현 검토, 코드 개선, 개발 보조
- **Gemini** — 아이디어 검토, 기술·구현 보조

세 도구 모두 사용한다. **버전별 개별 프롬프트·담당 기능·실행 결과는 별도의 사용 기록이 확인되는 범위에서만 기재**한다. 특정 AI가 특정 코드를 작성했다고 근거 없이 단정하지 않는다.

## 3.3 실행 방법 (v0.4)

1. 프로젝트 폴더를 VS Code에서 연다.
2. `index.html`과 같은 위치에 `data/`, `css/`, `js/`, `asset/`가 있는지 확인한다.
3. Live Server 또는 로컬 HTTP 서버로 `index.html`을 실행한다. 파일을 직접 더블클릭하는 `file://` 방식은 JSON `fetch`가 제한될 수 있다.
4. 책방 탐색에서 300개 서점 로딩, A/J 배지, 후기/코스 저장을 확인한다.

## 3.4 API 데이터 갱신 (v0.3 이상)

`KCISA_SERVICE_KEY` 환경변수를 설정한 뒤 `python scripts/fetch_bookstores.py`를 실행해 API JSON을 갱신한다. 수집 결과는 검토 후 반영한다. **서비스 키를 README, JSON, 브라우저 JavaScript 또는 공개 GitHub 저장소에 넣지 않는다.**

## 3.5 데이터 품질·보안 주의사항

- 외부 API에서 가져온 정보는 수집 시점의 정보이므로 방문 전 실제 영업 여부를 확인해야 한다.
- 서점 데이터의 누락값을 임의로 만들어 채우지 않는다.
- 정적 JSON의 공개 배포와 개인 후기의 클라우드 공유는 서로 다른 문제다.
- LocalStorage의 데모 로그인은 실제 인증/보안 시스템을 대체하지 않는다.
- 새로운 버전에서는 데이터 수, 중복 기준, 필드 구조, 저장 위치, 폴더 변경을 변경이력에 함께 기록한다.
